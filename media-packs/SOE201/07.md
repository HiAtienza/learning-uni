# Selection, Projection and External Sorting

## In 60 Seconds

An index can reduce transferred blocks yet increase expensive seeks. Suppose a file occupies 400 blocks and an unclustered index matches 100 scattered records. With index height 4, transfer time 0.1 ms and seek time 4 ms, a full scan costs 44 ms, while the lecture's pessimistic secondary-index model costs 426.4 ms. The access path matters more than the mere existence of an index. This supplementary calculation uses Lecture5a pp.5,10 and the disk model from Unit 06.

This edition integrates the verified 12 October archive: Lecture5a, 23 pages, dated 10 October 2026. It is a new web lesson, not a claim that the file was first released this week. Week 6 optimisation sources are visible on Learning Mall but remain pending acquisition. Prerequisites: Unit 01 storage, Units 02–04 indexes, Unit 05 algebra and Unit 06 cost units.

## Select an Access Path With Explicit Assumptions

Let b_r be file blocks, h the lecture's number of index-node accesses, b the consecutive matching data blocks and k the matching records. For cold accesses, retain transfers B and seeks S separately, then compute $T=B t_T+S t_S$.

| Access path | Transfers B | Seeks S | Conditions |
|---|---:|---:|---|
| Linear scan | $b_r$ | 1 | Contiguous relation; test every record |
| Successful equality scan on a key, average | $b_r/2$ | 1 | Source average model; absence may need full scan |
| Binary search | $\lceil\log_2 b_r\rceil$ plus matching blocks | Same search count, then retrieval | File physically ordered on equality attribute |
| Candidate-key B+ lookup | $h+1$ | $h+1$ | One matching data record |
| Clustered non-key equality | $h+b$ | $h+1$ | Matching records contiguous |
| Unclustered non-key equality, pessimistic | $h+k$ | $h+k$ | Each matching record may be on another block |

The deck calls the clustered non-key case a primary index. Keep its physical locality assumption explicit rather than assuming every primary-key definition implies clustering. Cached index pages, repeated data blocks and storage hardware can change actual costs. These estimates are not measured runtimes. Source: Lecture5a pp.4–10.

## Handle Ranges and Boolean Conditions Completely

For a clustered lower range, seek to the first qualifying key then read the following blocks sequentially. For a prefix range ending at an upper bound, a scan from the start may avoid unnecessary index seeks. An unclustered range can fetch many scattered blocks, so compare against a full scan.

For an AND, one selective indexed condition may generate candidates; test the remaining conditions on every candidate. A suitable composite index is another possibility. For an OR, union the candidate pointers from every disjunct and remove duplicate pointers before retrieval. If any branch lacks a complete access path, its matches still need finding, often by scanning. Lecture5a p.13 loosely says some indexes may be available; using only indexed branches would silently lose valid OR results. Negation requires the complement relative to the relation, not simply returning the positive matches. Source: Lecture5a pp.11–14; the completeness qualification is local reasoning about the stated predicate.

## Project Columns and Remove Duplicates

Relational projection drops unwanted attributes and eliminates duplicate resulting tuples. Sorting the projected tuples makes duplicates adjacent; hashing sends equal tuples to the same group. SQL SELECT without DISTINCT may preserve duplicates, so do not transfer set-algebra semantics automatically to SQL. An index orders references logically; following a secondary index is not equivalent to physically sorting the data and may cause an I/O per tuple. Source: Lecture5a pp.15–16; algebra/SQL distinction retained from Unit 05.

## Create Runs Before Merging

For b blocks and M memory frames, read up to M blocks, sort them in memory and write each sorted run. Initially there are $N=\lceil b/M\rceil$ runs. A merge reserves input buffers for participating runs and an output buffer. With one frame per buffer, merge at most M−1 runs; with b_b frames per buffer, fan-in is $F=\lfloor M/b_b\rfloor-1$. Require F≥2 before using logarithmic multipass formulas. More buffering improves sequential I/O but reduces fan-in and may add a pass. Source: Lecture5a pp.17–21.

For the supplied b=12, M=3 example, runs shrink 4→2→1 in two merge passes. The initial groups of three are sorted separately, then paired and finally merged. The repeated key a has payloads 19 and 14: the figure sorts by key, with equal-key ordering not specified as a stable-sort requirement. Source: Lecture5a p.20; Lab4 Q3 p.5.

## Count Transfers and Seeks With One Output Convention

For b>M and $P=\lceil\log_F\lceil b/M\rceil\rceil$, the source omits the final output write:

$$B=b(2P+1),\qquad S=2\lceil b/M\rceil+\lceil b/b_b\rceil(2P-1).$$

Initial run generation reads and writes 2b blocks; each intermediate merge reads and writes 2b; the final merge reads b. If the final sorted file must be stored, add b writes and $\lceil b/b_b\rceil$ seeks. For b=12, M=3, b_b=1, P=2 gives 60 transfers and 44 seeks when streamed; storing the final file gives 72 and 56. An in-memory input is a separate case; do not apply a negative-pass term mechanically. Source: Lecture5a pp.21–22.

## Return to the Access-Path Decision

For the opening example, scan: $400(0.1)+1(4)=44$ ms. Unclustered index: $104(0.1+4)=426.4$ ms. A clustered lookup retrieving eight consecutive blocks would instead cost $12(0.1)+5(4)=21.2$ ms. The final comparison requires selectivity, locality, available ordering, memory and a consistent output policy. These are supplementary examples with stated parameters, not new measured results.

## Atomic recall

### Card 01 — Why can fewer transfers still mean a slower plan?

> [!success]- Answer
> Seek time may dominate: compare B×tT+S×tS using the same time unit.
>
> Source: Lecture5a pp.6–10.

### Card 02 — What enables binary search on a file?

> [!success]- Answer
> Physical ordering on the selection attribute, not merely the existence of some index.
>
> Source: Lecture5a p.6.

### Card 03 — What changes between clustered and unclustered equality retrieval?

> [!success]- Answer
> Clustered matches occupy consecutive blocks; scattered matches can require an I/O and seek for each record.
>
> Source: Lecture5a pp.8–10.

### Card 04 — What must an OR access plan cover?

> [!success]- Answer
> Every disjunct, including unindexed branches, and duplicate candidate pointers must not cause duplicate set results.
>
> Source: Lecture5a p.13, local completeness clarification.

### Card 05 — Why can projection be expensive?

> [!success]- Answer
> Removing duplicate projected tuples requires grouping, often by sorting or hashing.
>
> Source: Lecture5a p.15.

### Card 06 — How many initial runs and which merge fan-in?

> [!success]- Answer
> $N=\lceil b/M\rceil$ and $F=\lfloor M/b_b\rfloor-1$, with F at least two for multipass merging.
>
> Source: Lecture5a pp.17–21.

### Card 07 — What does the external-sort cost formula omit?

> [!success]- Answer
> The final sorted-output write; add it when a persistent sorted file is required.
>
> Source: Lecture5a p.21.

## Worked practice

### Problem 1 — Choose between locality assumptions

SUPPLEMENTARY PRACTICE. Compare full scan, clustered index and unclustered index for b_r=400, h=4, b=8, k=100, tT=0.1 ms, tS=4 ms. Source: Lecture5a pp.5,8,10.

> [!tip]- Hint
> Keep B and S separate until the final multiplication.

> [!success]- Solution
> Scan: B=400,S=1,T=44 ms. Clustered: B=12,S=5,T=21.2 ms. Unclustered pessimistic: B=S=104,T=426.4 ms. Under these assumptions the clustered path wins; the unclustered path loses despite fewer transfers than scanning.

### Problem 2 — Trace the supplied external sort

SOURCE EXERCISE. b=12, M=3, b_b=1. Give run counts, merge passes and total transfers/seeks with and without final output writing. Source: Lecture5a p.22; Lab4 Q3 p.5.

> [!tip]- Hint
> Initial runs are ceil(12/3)=4 and each merge combines two.

> [!success]- Solution
> Four initial runs merge 4→2→1, so P=2. Streamed transfers:24+24+12=60. Seeks:2×4+12×(2×2−1)=44. Materialised output adds 12 transfers and 12 seeks, giving72/56. Equal-key payload order is not a required stable-sort property.

### Problem 3 — Audit an incomplete OR plan

SUPPLEMENTARY PRACTICE. For A=1 OR B=2, only A is indexed. Is returning the A index matches complete? Source: Lecture5a p.13.

> [!tip]- Hint
> Consider a tuple satisfying only B=2.

> [!success]- Solution
> No. Such a tuple is a valid result but absent from the A candidate set. Scan for the uncovered branch or scan the whole relation, then combine completely and eliminate duplicate pointers. Existing indexes do not remove predicate-completeness obligations.
